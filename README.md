> **出处：@夏**

---

## 这是什么

一条完整的**视频拉片流水线**。丢进一条片子（本地文件或链接），自动切分镜头、抽取代表帧、量化剪辑节奏与声音结构，最后产出一份自包含 HTML 拉片报告：逐镜拆解表 + 方法论提炼 + 可复用清单。

核心不是「描述画面」，而是回答三个问题：

> **它用什么手法？为什么有效？我怎么抄？**

---

## 与相邻技能的边界

| 技能 | 方向 | 什么时候用它 |
|---|---|---|
| `video-downloader` | 拿片子 | 有链接还没素材，先走它 |
| `video-shotcraft` | 做片子 | 用户要「做一条宣传片」 |
| **video-teardown（本技能）** | **拆片子** | 用户要分析已有片子 |

---

## 工作流

| 步骤 | 做什么 | 关键命令 / 要点 |
|---|---|---|
| Step 0 | 拿素材 | `video-downloader` → `yt-dlp` → 平台 API 手搓 → 抓包（最后手段） |
| Step 1 | 读参数 | `ffprobe` 取时长 / 分辨率 / 编码 / fps |
| Step 2 | 场景检测切镜 | `ffmpeg select='gt(scene,0.35)'`，**必须去闪频**（合并 <0.5s 碎片） |
| Step 3 | 抽代表帧 | 每镜取 `start + dur*0.45`，避开转场首尾 |
| Step 4 | 拼接触印相表 | `ffmpeg tile` 拼网格，转 JPEG 内联进 HTML |
| Step 5 | 声音结构 | `silencedetect` 气口密度 + `loudnorm` 响度 / LRA / 真峰值 |
| Step 6 | 读图分析 | 逐张读接触表，记景别 / 机位 / 构图 / 色彩纪律 / 花字 |
| Step 6.1 | **读图失效时的替代管线** | whisper 转录旁白 + tesseract OCR 花字 + 帧特征自动归类 |
| Step 7 | 出报告 | 自包含 HTML，严格按交付参考版式 |

## 报告产出规范（对齐交付参考）

自包含 HTML（图片 base64 内联，零外部依赖，零 emoji），**14 块固定分节**，顺序不可动：

| # | 分节 | 硬要求 |
|---|---|---|
| 1 | 标题区 | `h1` + `.thin` 副标题「拉片报告 · 片名 · 时长」 |
| 2 | 影片档案 | `.meta` **六格卡片**：片长 / 镜头数 / 平均镜头 / 规格 / 剪辑点检出（原检 N → 去闪 M）/ 响度 |
| 3 | **开场论点段** | 点明「这条片形式上是什么」+ 几层可抄价值（不可一上来就列表） |
| 4 | 核心公式 `THE FORMULA` | 编号列表 6–8 条，每条引原文旁白 / 花字作证据 |
| 5 | 结构与节奏曲线 `STRUCTURE` | **内联 SVG 柱图**（红 = 降速段）+ 分幕汇总表 |
| 6 | 分幕配接触表图 | 每幕一图，图文对照 |
| 7 | 三个关键帧 `KEY FRAMES` | 三栏 |
| 8 | 逐镜头拆解表 `SHOT LIST` | 七列；旁白 / 花字标【旁白】/【花字】并加 `.vo` 砖红 |
| 9 | 声音结构 `SOUND` | 覆盖模式 + 气口 + 响度；末尾「可学的点」callout |
| 10 | 色彩与光 `COLOR & LIGHT` | 配色纪律 + 光 + 景深 |
| 11 | 清单 `CHECKLIST` | 6–10 条，动作必须可立刻执行 |
| 12 | 反向提醒 | 这套手法什么时候会翻车 |
| 13 | 给你自己的用法 `FOR YOU` | **必须绑用户真实项目**，别写「可用于短视频」 |
| 14 | foot | 拉片方法 + 素材来源 + 「仅供学习研究」 |

样式令牌：砖红 `#b3382c`、宋体（Songti SC）标题、PingFang SC 正文 15px、最大宽 900px。

## 平台坑表（本地实测）

| 平台 | 现状 | 绕法 |
|---|---|---|
| B站 | `yt-dlp` 请求网页**必被 412** | 手动调 API（搜 bvid → 取 cid → 取 DASH）；下分片**必须带 Referer**，否则 403 |
| 微信视频号 | 网页端**已拿不到任何素材**（接口 401、分享页空壳 SPA、`yt-dlp` 无提取器） | ① 找同源跨平台镜像；② 微信内播放 + MITM 抓包（代价高，先问用户） |
| YouTube | `yt-dlp` 老版本报 **HTTP 403** | **升级 yt-dlp**（`python3 -m pip install -U yt-dlp --user`）。别换 `player_client=web`，会报 format not available |

## 读图失效时的替代管线（Step 6.1）

有些会话里读图会返回 `current model does not support images`——**此时绝不能靠猜画面编造分析**。改用程序化管线：

| 目标 | 手段 |
|---|---|
| 【旁白】 | `whisper-cli`（whisper.cpp）本地转录，按时码与镜头区间重叠匹配 |
| 【花字 / 界面文字】 | `tesseract` + `chi_sim` 语言包（OCR 前放大到 1000px 宽转灰度，小字识别率明显提升） |
| 景别 / 镜头类型 | Pillow + numpy 算亮度 / 饱和度 / 肤色占比 / 边缘密度 / 色彩丰富度 → 自动归类（口播 / 录屏 / 标题卡 / B-roll） |

对长片（>10 分钟、百镜以上）尤其划算：肉眼逐张读上百帧不可行，程序化反而更全。

## 实测案例

以 YouTube 长片《我給自己招了4個AI員工，每週省下8小時！》（李厂长来了）跑通全流程：

| 指标 | 实测值 |
|---|---|
| 片长 / 规格 | 929.5s / 1920×1080 / 30fps / AV1 |
| 镜头数 | 172（原检 175，去闪频后 172） |
| 平均镜头 | 5.4s（最长 31s，<1s 快切 16 个） |
| 镜头类型 | 口播 99 / 录屏 64 / B-roll 8 |
| 响度 | −14.9 LUFS、真峰值 +1.2 dBTP、LRA 3.0 LU |
| 分幕 | 七幕（Hook → 概念 → 管家 → 制作人 → 翻译·陪练 → 外部数据 → 行动清单） |

## 安装

把 `SKILL.md` 放进用户级 skill 目录即可跨项目生效：

```bash
mkdir -p ~/.workbuddy/skills/video-teardown
cp SKILL.md ~/.workbuddy/skills/video-teardown/
```

依赖：`ffmpeg` / `ffprobe` / `yt-dlp`（视频管线）、`whisper-cli`（旁白转录，可选）、`tesseract` + `chi_sim`（花字 OCR，可选）、`Pillow` + `numpy`（帧特征，可选）。
